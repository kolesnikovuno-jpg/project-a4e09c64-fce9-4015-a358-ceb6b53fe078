# Egg Engine v0.3 — личный Google Drive как хранилище материалов

**Статус:** реализован минимальный реестр ссылок и экспорт состояния в тестовой ветке; автоматическое сохранение файлов в Google Drive **не реализовано**. Синхронизация с Google Drive не должна симулироваться: без разрешения пользователя и подключённого Drive-инструмента ИИ не сможет создать файл или проверить существование.

## Архитектура

**Пользователь ↔ привычный ИИ ↔ Яйцо (движок)**

Параллельно **привычный ИИ ↔ Google Drive пользователя** через поддерживаемое подключение/плагин с его разрешением.

Движок хранит структуру проекта, задачи восьми сфер, итерации, авторские решения и **реестр внешних файлов**: provider, file ID, название, MIME-тип, URL (если получен от Drive), версия регистрации, задача/сфера, автор регистрации и статус подтверждения.

Google Drive держит **содержимое** документа, эскиза, фото, расчёта и пр. Яйцо не копирует байты файлов и не получает OAuth-токен Google. Необходимо учитывать, что права Google Drive действуют независимо от прав Яйца: наличие ссылки не гарантирует доступ.

### Рабочий пример

1. Автор в ChatGPT: «Разработай три варианта кресла, работая через Яйцо. Результаты сохрани в мой Google Drive».
2. ChatGPT с **реально подключённым** Drive создаёт папку/файл (если инструмент позволяет) и получает возвращённые Google Drive \`fileId\` и ссылку.
3. ChatGPT с отдельным **токеном Яйца для одного проекта** запрашивает \`GET /api/egg?projectId=<uuid>\`; находит нужную задачу/сферу.
4. Вызывает \`POST /api/egg\` c командой \`register_file\`:
   \`\`\`json
   {
     "command": "register_file",
     "projectId": "<uuid>",
     "expectedRevision": 4,
     "provider": "google_drive",
     "fileId": "<file ID from Drive>",
     "title": "Кресло — эскизы",
     "mimeType": "application/pdf",
     "collectionKey": "chair-design/sketches",
     "taskId": "task-2",
     "webUrl": "https://drive.google.com/file/d/<file ID from Drive>/view"
   }
   \`\`\`
   Значения ID и ссылок — **пример формы**, их нельзя придумывать. \`webUrl\` необязателен и должен вести именно к переданному файлу на \`drive.google.com\` или \`docs.google.com\`. Движок отклонит неподходящую ссылку, но пока **не проверяет файл у Google**.
5. В Яйце появляется запись со статусом **reported** («ИИ сообщил ссылку»).
6. Автор открывает файл в своём Drive и, убедившись, что он соответствует результату, подтверждает \`confirm_file\` с \`artifactId\`. Статус становится **author_confirmed**. Это означает подтверждение Автором, не независимую проверку Google API.

**Права:** зарегистрировать ссылку может внешний ИИ с ограниченным разрешением \`contribute\`; подтвердить её может только Автор через проверенную пользовательскую сессию. Внешний ИИ не может утверждать Ядро и переходить на новый уровень.

## Реализовано

- \`src/lib/eggArtifacts.ts\`: \`registerDriveReference\`, \`confirmDriveReference\`, \`exportEggManifest\` и проверки URL/ID.
- \`src/lib/eggEngine.ts\`: дополнительные события и необязательный массив \`artifacts\`, совместимый со старыми проектами.
- \`src/lib/eggCommands.ts\`: команды \`register_file\`, \`confirm_file\`, поле \`files\` в ответе состояния.
- \`api/egg.ts\`: обработка команд через существующий API с проверкой прав и ревизии.
- \`GET /api/egg?projectId=<uuid>&format=manifest\` — **только Автор**, отдаёт переносимый JSON с заголовком скачивания \`egg-project-<uuid>.json\`. Экспортирует всю структуру проекта и ссылки, **не скачивает и не вкладывает содержимое файлов из Drive**.
- \`src/test/EggArtifacts.test.ts\`: проверки связей с задачей, последовательности регистрации, авторского подтверждения, экспорта и недоверенных URL.

**Версии:** \`version\` — это порядковый номер записи в конкретной \`collectionKey\`. Он *не совпадает* автоматически с Google Drive revision ID. Повторно зарегистрированная ссылка не доказывает, что содержимое файла изменилось.

**Совместимость:** старые проекты \`egg.engine/0.1\` без \`artifacts\` продолжают читаться; новые создаются с пустым реестром. Необходимая ранее подготовленная миграция JSONB не изменяется.

## Важно для будущей коммерческой модели

- У Яйца нет обязательного дополнительного чата и нет требования хранить крупные пользовательские файлы.
- Google Drive остаётся под управлением пользователя, но он может отозвать доступ ИИ либо удалить файл, после чего старая ссылка перестанет работать.
- Плата за движок не включает автоматически подписку ИИ, облачное хранилище и стоимость токенов пользователя.
- Движок должен поддерживать несколько провайдеров без принудительной миграции данных; текущий пилот **ограничен Google Drive**.

## Что ещё требуется до работающей интеграции

1. Тестовый Supabase с применённой миграцией, установленными на сервере секретами и авторизация владельца (пока не включено).
2. Подключение реального ИИ, умеющего **оба действия**: сохранить файл на Google Drive и вызвать Яйцо (через API/MCP) — доступность зависит от платформы и разрешений.
3. Контроль фактического \`fileId\`, Google Drive OAuth и проверка прав, если потребуется полноценная проверка файла; токены и refresh-токены не передаются ИИ в виде текста.
4. UI страницы Автора: список результатов, ссылки на материалы, действие «Подтвердить», скачивание манифеста.
5. Резервное копирование **самих файлов**, если требуется полный автономный архив, и восстановление/импорт манифеста. Сейчас реализован **экспорт без восстановления**.

### Позиция методики

**Интеллект сменный. Движок постоянный. Файлы пользователя — в выбранном им хранилище.**
Эта архитектура является проверяемой проектной гипотезой, не доказательством спроса или универсальности.
