# EGG — протокол команды «Как дела?»

Статус: утверждён автором 2026-11-23. Применяется к любому проекту EGG, в том числе Lyra.

## Триггеры
- «Как дела?» / «Что нового?» в контексте проекта: диагностика всего проекта, не только последней обсуждавшейся сферы.
- «Продолжай»: выполнение следующего допустимого действия по текущим приоритетам; внешние расходы, публикации и необратимые изменения — только в рамках действующих разрешений и ограничений.

## Источники и достоверность
1. Определить активный проект и его цель, текущий уровень и утверждённые ограничения.
2. Проверить доступные актуальные источники (репозиторий/деплой, БД, рекламные каналы, заявки, документы и т. д.) по необходимости.
3. Разделять «проверено сейчас», «из предыдущих данных», «гипотеза», «нет данных». Не считать отсутствие метрик нулём без проверки.
4. Не выдавать план за выполненную операцию. Указывать дату проверки и степень уверенности.

## Сбор результатов сфер
Поток A: Маркетинг → Дизайн → Тестдрайв → Коммерция.
Поток B: Право → Производство → Комплектация → Ритейл.
Для каждой сферы: статус, изменение с прошлого отчёта, подтверждённые результаты, блокеры, требуемые данные, следующее действие и исполнитель (ИИ/автор/специалист).
Проверять также вертикаль Идея ↔ Материальное, внешнее поле, белок (общее информационное поле проекта), ДНК, желток (синтез), актуальный уровень Идея → Концепт → Проект → Прототип → Объект.

## Синтез желтка — формат ответа
1. Состояние проекта относительно цели: достигнуто / в работе / риск / неизвестно.
2. Изменения и результаты восьми сфер; не расширять отчёт пустыми подробностями.
3. Приоритеты (максимум три) по влиянию на цель, срочности, зависимости и ресурсу.
4. Что ИИ делает самостоятельно и что требует внешних специалистов.
5. Только конкретные решения автора: зачем, какие варианты, ресурс/риск, срок если известен. Если участие автора не нужно — прямо сказать.
6. Следующий измеримый контрольный показатель и действие.

## Правила управления
- Не перекладывать на автора поиск информации и подготовку, которые сферы могут выполнить сами.
- Не подменять согласование автора: затраты, новые обязательства и юридические решения требуют разрешения, если оно ещё не дано.
- При остановке критического процесса (например, рекламы) — уведомить через доступный механизм мониторинга, а не ждать команды «Как дела?».
- Для Lyra учитывать рекламный лимит 100 грн/день и 3000 грн/30 дней как верхние ограничения, а не распоряжение потратить бюджет; различать посещения владельца и внешний спрос.
- Протокол определяет поведение отчёта; сам по себе не означает, что создан новый серверный оркестратор или интерфейс EGG.

## Диагностический цикл сферы (уточнение из пилота Lyra, 2026-11-23)
Каждая сфера обязана вести локальный цикл: цель → фактическое состояние → отклонение → проверяемые причины → действие в пределах полномочий → проверка результата → структурированный вывод в желток.
- При отсутствии результата сначала установить, произошло ли предыдущее необходимое событие. Пример: ноль кликов при нуле показов — это не доказательство отсутствия спроса; маркетинг сначала проверяет доставку рекламы.
- Различать установленную причину и гипотезы. Ноль показов после восстановления ключевых слов — установленное состояние по данным автора; недостаточная ставка, малый поисковый спрос, настройки таргетинга — гипотезы до проверки.
- Сфера самостоятельно собирает доступные сведения из белка и внешнего поля, запрашивает недостающие данные и привлекает инструменты/специалистов по разрешённой процедуре.
- Не подменять диагностику ожиданием: задать контрольную точку, условие эскалации и план следующей проверки. Не обещать фонового контроля, если не существует настроенного мониторинга.
- Вывод для желтка: «что это означает для цели», «что делаем», «когда и по какому сигналу перепроверим», «нужно ли решение автора». Технические подробности — только если они меняют решение.
- «Как дела?» отвечает управленческим синтезом, а не выгрузкой телеметрии: краткое положение относительно цели, узкое место, приоритет, действие, участие автора. Подробности раскрываются по запросу.

### Проверочный пример — Lyra
Цель: проверка платёжеспособного спроса и ориентир два заказа в месяц. Реклама одобрена и ключевые слова включены, но автор сообщает о нуле показов. Вывод: тест спроса пока не даёт рыночных данных, а не «кресло неинтересно». Приоритет сферы маркетинга: установить причину отсутствия показов; не повышать бюджет без решения автора. Участие автора: не требуется, пока не возникнет конкретное согласование.
