# EGG — прямое подключение OpenAI API

Обновление: 16 ноября 2026. Контур GitHub + Vercel, без Lovable.

## Почему
В Google AI Studio наблюдались пределы для Gemini Flash, периодические ответы 429. Это не ошибка Vercel и не повреждение EGG. Автор может перейти на собственный оплаченный OpenAI API (пополнение через platform.openai.com, отдельно от ChatGPT Plus).

## Настройка — одно секретное значение
1. В [OpenAI Platform API Keys](https://platform.openai.com/api-keys) в том проекте/организации, где пополнен баланс, создать **новый секретный ключ**. Не копировать его в чат, GitHub или клиентские файлы.
2. На Vercel открыть проект `project-a4e09c64-fce9-4015-a358-ceb6b53fe078` → Settings → Environment Variables.
3. Добавить `OPENAI_API_KEY` с **секретным** значением; Production — обязательно для `egg.kolesnikov.studio`. При тестировании preview добавить отдельно для ветки `integration/egg-unified-2026-11-12`.
4. Пересобрать/повторно развернуть приложение после добавления секрета. Переменные окружения действуют для новых сборок, не для уже созданных.
5. Проверить тестовый preflight или выполнить **только нужный текущий шаг** EGG; убедиться по защищённым runtime-логам, что `provider: direct_openai`. Не запускать прошлые сферы заново.
6. В Platform → Usage следить за токенами и расходом. В Billing проверить, не включилось ли автоматическое пополнение. Наличие предоплаты не отменяет rate limits.

## Выбор модели
При установленном `OPENAI_API_KEY` EGG **предпочитает прямой OpenAI Responses API** перед Gemini и Vercel AI Gateway. По умолчанию: `gpt-6-luna` — экономичный вариант. Для более сильной модели можно задать `EGG_AUTOMATION_MODEL` в Vercel, после чего потребуется новая сборка. Выбирать только реальный модельный ID, доступный в оплаченной API организации. Код не делает незаметного fallback на Gemini при ошибке OpenAI: ошибка сохраняет текущий шаг.

Если `OPENAI_API_KEY` отсутствует, EGG ведёт себя как раньше: сначала настроенный Gemini, затем Gateway. Удаление или отключение переменной и новая сборка возвращают прежний маршрут.

## Защита данных и затрат
- `OPENAI_API_KEY` используется **только на сервере** `api/egg-flow-ai.ts`, не в браузере; в историю проекта не записывается.
- Не показывать значение ключа в логах, запросах проверки или сообщениях.
- Состояние сфер, утверждённая ДНК, два потока и выбор Автора сохраняются в EGG независимо от провайдера.
- Не делать автоматических повторов при ошибке 429; сохранённые шаги не пересчитывать.
- Пока действует консервативная клиентская пауза 17 секунд, созданная для прежнего бесплатного лимита Gemini; при реальных нагрузочных тестах OpenAI её можно настроить отдельно.
- Минимальный бюджет и модель нужно проверять по актуальным официальным тарифам: стоимость определяется отдельно входящими и исходящими токенами (включая платные токены рассуждения) и обработкой изображений.
- При использовании второго устройства отдельные вызовы не координируются серверной глобальной очередью; не считать локальный throttle гарантией соблюдения общего лимита.


## Текущий Vercel-контекст (проверено 16.11.2026)

На момент проверки `OPENAI_API_KEY` добавлен **только в Production**. При этом рабочий домен `egg.kolesnikov.studio` связан со сборкой ветки `integration/egg-unified-2026-11-12`, которая выполняется в **Preview environment** (проверено по журналам Vercel). В Preview переменная отсутствует. Требуется отдельно добавить `OPENAI_API_KEY` с целевым окружением `Preview` и, желательно, с ограничением на эту конкретную ветку. Значение ключа вводится **только пользователем в Vercel**, без чтения Production-секрета инструментами.

В Preview уже задана `EGG_AUTOMATION_MODEL=google/gemini-2.5-flash`. После выбора прямого OpenAI API сервер **игнорирует такой provider-prefixed ID** и использует `gpt-6-luna` по умолчанию. Это позволяет переключить провайдер без второй ручной правки. Без `OPENAI_API_KEY` существующий Gemini остаётся активен.

После добавления Preview-ключа необходимо **создать новую сборку** (не только обновить страницу), чтобы функция увидела новый серверный секрет. Проверка провайдера — безопасным отдельным preflight при наличии готовой авторской сессии; не перезапускать утверждённые сферы. Облачный лог должен показывать только `direct_openai`, без ключа.
