## Где реально находится код движка

Сравнение GitHub `main` с `prototype/design-brief-sketch-gates` показало **588 коммитов впереди / 25 позади** и множество отсутствующих в main модулей. Это НЕ безопасный fast-forward и НЕ повод сливать ветку целиком.

Исходники в ветках разработки:
- `src/lib/eggEngine.ts`: восемь сфер, граф направленных передач, задачи, свидетельства, решения Автора, уровни и итерации.
- `src/lib/eggFlowCycle.ts`, `eggCommands.ts`, `eggSphereIntelligence.ts`: циклы и логика заданий.
- `src/lib/eggArtifacts.ts`, `eggDocumentation.ts`, `eggVisualHistory.ts`, `eggYolkState.ts`, `eggYolkTimeline.ts`: артефакты, документация, визуальные состояния Желтка (степень готовности различается).
- `src/components/egg/EggSpherePanel.tsx` (в `prototype/egg-yolk-idea-loop`): режимы auto/symbiosis/manual, предметные роли, заметки; **наличие переключателя не доказывает работающий автоматический режим**.
- `src/components/egg/EggSphereWorkspace.tsx`, `EggYolkExperience.tsx`, `EggYolkViewer.tsx`: рабочие интерфейсы.
- `api/egg.ts`, `api/egg-project-state.ts`, `api/mcp.ts`, `egg-server/migrations/20261102235000_egg_engine_tables.sql`: серверная и интеграционная часть, требующая отдельной проверки окружения, БД и прав.
- `src/components/unocalc/UnoEggScene.tsx` и `UnoEggIdeaCyclePanel.tsx`, `UnoEggDesignLoopPanel.tsx`, `UnoEggFilePanel.tsx`: подтверждённый визуальный слой и локальные сценарии.

## Архитектурные правила, которые нельзя терять

Документы в `prototype/egg-yolk-idea-loop`:
- `docs/EGG_ARCHITECTURE_BASELINE.md`: три независимых выхода Идеи — ДНК в Желток, поток I, поток II; авторские решения; версия и источник каждого утверждения.
- `docs/egg-architecture-principles-2026-11-09.md`: два прямых маршрута, история итераций, три режима работы, визуальный центр Желтка.
- `docs/egg-nine-kernels-domain-contracts-v02.md`: предметные контракты восьми сфер + Желтка.
- `docs/egg-system-orchestration-nine-kernels-v02.md`: оркестрация, события, контроль версий, ограничения полномочий.

Поток I: Идея → Маркетинг → Дизайн → Тестдрайв → Коммерция → Желток.
Поток II: Идея → Право → Производство → Комплектация → Ритейл → Желток.
ДНК поступает в Желток независимо от обоих потоков. Автор утверждает изменение ДНК. Факты, гипотезы и предложения не смешиваются.

## Проверенные разрывы

1. `main` не содержит многих исходников EGG Engine и компонентов; визуальная рабочая сборка живёт в другой ветке.
2. Визуальная страница `/unocalc` и проектная страница `/egg?project=...` имеют разную интеграцию. Нельзя считать их одним и тем же функциональным приложением.
3. Документы об оркестрации и девяти ядрах имеют статус спецификаций; не все описанные функции реализованы.
4. Режимы auto/symbiosis/manual частично отражены в UI; полноценная автоматизация и безопасность не подтверждены.
5. Реальные данные Supabase, миграции и права доступа этим сравнением **не проверялись**.

## Порядок безопасной интеграции

1. Сохранить утверждённый визуальный слой неизменным.
2. Сопоставить идентификаторы сфер, маршруты и события UI с `eggEngine.ts`, API и проектным состоянием.
3. Сделать адаптер UI ↔ Engine без дублирования источника истины; отдельно обеспечить сохранение/версионирование и авторские гейты.
4. Вводить режимы по сферам с честной маркировкой готовности; тестировать проектный цикл и оба потока.
5. Только после проверок перенести интегрированную версию на постоянный адрес; не выполнять массовый merge и не удалять старые ветки/данные.

**Запрет на автоматическое принятие концепции, удаление истории, выдумывание подтверждений и незаметную смену ДНК.**
