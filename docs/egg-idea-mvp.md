# EGG · MVP сферы «Идея»

Дата: 2026-11-04. Экспериментальная ветка `prototype/idea-concept-workbench`, без изменений production.

## Смысл

«Идея» находится на входе EGG. Она преобразует неизменяемый авторский замысел в **концепцию**, которую можно представить текстом, ссылкой на графику или их сочетанием.

На выходе возникают два потока:

1. **Информационная оболочка**: принятая концепция попадает в EGG Engine Core и становится доступным внутренним контекстом функциональных сфер, не заменяя исходную идею.
2. **Проработка**: концепция может содержать до восьми конкретных вопросов для отдельных сфер; Автор выпускает их по одному в реальный EGG Engine.

Предложенные вопросы не равны доказанной необходимости работы всех сфер. Открытые смыслы и неизвестные параметры не обязаны заранее формализоваться.

## Механика и полномочия

- `propose_concept` создаёт **неутверждённую** версию. Автор может сформулировать её в EGG UI, подключённый AI может направить через MCP `egg_propose_concept`, если у него есть действительный проектный ключ с правом `contribute`.
- Пока есть нерассмотренная версия, следующую предложить нельзя. Изменение оформляется новой версией, не переписыванием старой.
- `decide_concept` выполняется только владельцем проекта через Author JWT: `accept` / `revise` / `reject`. Причина/направление сохраняются.
- Последняя версия со статусом `accepted` представляется как действующая концепция в `readCore` и в визуальной панели «желтка».
- `route_concept_question` только Автором создаёт задачу с `sourceConceptId` и `sourceQuestionIndex`, чтобы сохранять происхождение. Повторное действие не дублирует задачу.
- Новая версия не стирает старые подтверждения и уже существующие задачи; если меняется концепция, связанные прежние задачи требуют содержательной проверки на актуальность.

## Реализовано

- Pure state transitions EGG Engine и API с CAS (optimistic concurrency/revision).
- Версионированные концепции в проектном JSON (опциональное поле `concepts`; старые проекты читаются без миграции).
- Интерфейс `EggIdeaWorkshop`: создание предложения, ссылка на графику, список вопросов, решение Автора, просмотр истории и ручное направление по сферам.
- Передача принятой концепции во внутреннее поле `EggSphereWorkspace`.
- Индикация принятой концепции в `EggYolkMonitor`.
- `EggIdeaDemo`: автономная локальная симуляция без авторизации, не взаимодействует с проектами.
- Серверный MCP-инструмент для **предложения**, но не утверждения AI-концепции.
- Юнит-тесты переходов, авторских границ и запрета автоматического утверждения.

## Не реализовано

- Самостоятельное AI-сжатие идеи внутри браузера без внешнего AI клиента.
- Генерация графики, загрузка локальных изображений и файлов из iPad (есть только ссылка).
- Автоматическое построение карты задач из текста концепции (кандидаты пока задаются человеком или подключённым AI).
- Единый интегральный отчёт по восьми сферам и авторское утверждение всей итерации.
- Повторные проходы уровня как отдельные сущности.
- Реальная 3D-динамика желтка, связанная с версиями концепции.

## Проверка

- `npm run egg:verify` в preview-ветке запускает Vitest, статическую проверку server API и Vite build.
- Сквозная проверка с пользовательским JWT и внешним MCP OAuth пока не подтверждена.
- Демо без регистрации иллюстративно; клики по нему не сохраняются на сервере.
