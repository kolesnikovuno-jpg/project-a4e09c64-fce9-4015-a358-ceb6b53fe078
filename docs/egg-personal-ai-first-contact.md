# EGG / первый контакт личного ИИ (v0.1)

## Разделение ответственности

- **Автор** регистрируется в EGG, создаёт проект, управляет ДНК и утверждает решения.
- **EGG Engine** хранит структуру проекта, уровни и итерации, состояние Яйца, работу восьми сфер и информацию для Желтка. EGG предоставляет API/MCP и ограничения полномочий.
- **Личный ИИ пользователя** подключается к EGG через поддерживаемый клиент. Он может прочитать разрешённые данные, обсуждать, исследовать и предлагать черновики в пределах предоставленных разрешений.
- **Облачное хранилище** пользователь подключает на стороне своего ИИ-клиента, а не к EGG. ИИ использует только реально доступные ему инструменты и разрешения.

## Первый контакт (MCP)

1. Пользователь подключает \`https://egg.kolesnikov.studio/api/mcp\` из своего ИИ-клиента (если клиент поддерживает произвольные MCP-серверы) и подтверждает доступ.
2. MCP \`initialize.instructions\` предлагает ИИ прочитать \`egg_get_onboarding_protocol\`.
3. \`egg_get_onboarding_protocol\` — инструмент только для чтения, без ID проекта. Он возвращает устройство EGG, ограничения полномочий и чек-лист проверки облака, не запрашивая данные клиента.
4. ИИ проверяет **на своей стороне**: есть ли доступный облачный инструмент; разрешено ли его использовать; выполняется ли безопасное чтение списка или метаданных. Сам факт наличия названия приложения не доказывает доступ.
5. Если ИИ не может проверить доступ, он сообщает \`unknown\`. Если доступ не предоставлен — \`not_connected\` или \`access_denied\`. \`verified\` допустим только после реального успешного разрешённого чтения.
6. ИИ сообщает человеку фактическую готовность и предлагает, при необходимости, подключить облако в настройках своего ИИ. Работу над идеями можно продолжать без облака; файловые операции не обещать.
7. Для работы с проектом ИИ получает ID от пользователя и вызывает \`egg_get_project_state\`. Регистрировать можно только реально созданные и подтверждённые самим источником файловые ссылки.
8. Черновики и предложения не утверждаются автоматически. Решения остаются у Автора.

## Ограничения протокола

- MCP-сервер EGG **не может прочитать** набор приложений, облачные токены или приватные чаты пользователя в ChatGPT или другом ИИ-клиенте.
- MCP-сервер **не гарантирует**, что сторонний клиент выполнит \`initialize.instructions\` или автоматически вызовет \`egg_get_onboarding_protocol\`. Для такого случая на странице \`/egg/connect\` есть кнопка «Скопировать инструкцию для моего ИИ».
- Ответ \`egg_get_onboarding_protocol\` всегда сообщает \`storageChecked:false\` и \`pending_ai_side_verification\`. Он **не является проверкой облака** и не может превращаться в «облако подключено» в UI.
- \`egg_register_drive_file\` работает с реальным идентификатором файла Google Drive, полученным от отдельного авторизованного инструмента. Это не общий интерфейс для других провайдеров. Поддержка иных хранилищ будет отдельным развитием регистрации ссылок.
- Не запрашивать у пользователя секреты, не переносить OAuth/ключи стороннего облака в EGG, не генерировать вымышленные идентификаторы файлов.
- Для первого чтения протокола требуется установленное MCP-подключение с нормальной авторизацией; отдельной анонимной возможности читать проекты нет.
- Сайт EGG не встраивает существующий приватный сеанс ChatGPT. Текущий рабочий путь — открытие личного чата с контекстом, а не копирование сессии пользователя.

## Текущий объём реализации

В тестовой ветке:
- \`src/lib/eggAiOnboarding.ts\` — провайдер-независимый структурированный протокол и инструкция.
- \`src/lib/eggMcpProtocol.ts\` — описание MCP-инструмента, read-only проверка аргументов, выдача протокола и инструкция инициализации.
- \`src/lib/eggAiHandoff.ts\` — напоминание при открытии диалога из сфер.
- \`src/pages/EggConnect.tsx\` — понятное описание, копирование инструкции и ручной резервный вариант.

Следующий самостоятельный этап — совместимые с провайдерами механизмы регистрации файлов и, при необходимости, подтверждение агентом проведённой проверки без доверия к неподтверждённым заявлениям.
