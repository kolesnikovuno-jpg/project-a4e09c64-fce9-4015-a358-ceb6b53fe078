# EGG — правила квоты ИИ и безопасного продолжения · v1
Дата фиксации: 2026-11-16. Статус: рабочий протокол, обязателен при изменении AI-интеграции.

## Наблюдаемый инцидент
- Google AI Studio / Default Gemini Project / Gemini 3 Flash показал **RPM 7/5** (пиковое значение за выбранные 28 дней), TPM 22.13K/250K и красный RPD без видимого числа.
- Логи Vercel подтвердили `provider: direct_gemini`, `model: gemini-3-flash-preview`, HTTP **429**. Нельзя по одному 429 автоматически утверждать, что это только минутная квота: превышение суточной (RPD) также возможно.
- Первый реальный цикл EGG проекта `f0841bf8-528f-4afe-a225-de53204faf0b` завершил 8/8 сфер, оба потока записаны, структурный Желток собран; семантический разбор Желтка отдельно зависит от ИИ.
- Лимиты Gemini — **на уровне Google Cloud проекта**; единый ключ, несколько браузеров, другие приложения разделяют квоту. Не путать с Vercel Build Rate Limit и тарифом ChatGPT.

## Контракт реализации
1. Движок делает **строго один AI-шаг на HTTP запрос**; подтверждённые результаты записываются с CAS-ревизией. Если следующий вызов получает 429, ранее сохранённые сферы НЕ перепроходятся и новая итерация НЕ создаётся.
2. Перед **первым** запуском допускается заряженный preflight для проверки доступа, но он тоже учитывается в темпе. При продолжении существующего цикла **не делать preflight**: он расходует лимит и может помешать последней сфере/Желтку.
3. На наблюдаемом лимите **5 RPM** применять консервативный зазор **17 секунд между стартами вызовов** одного браузера. Он действует для главного цикла, отдельной сферы, Диалога «Идея» и «Материального». Уважать отмену ожидания и показывать, почему запрос не начат сразу.
4. В одном браузере сохранять общий `next-request-at` в localStorage; это лишь *мягкое клиентское ограничение*. Оно не обеспечивает атомарную межвкладочную блокировку и **не защищает общую квоту на нескольких устройствах/других приложениях**. Для большого числа пользователей требуется *серверная общая очередь / квотный регулятор* с транзакционным счётчиком и управлением RPD/TPM.
5. Ответ 429: извлекать только разрешённые признаки `Retry-After` / Gemini `RetryInfo.retryDelay` и грубую классификацию `minute|daily|unknown` по `QuotaFailure`, если она реально присутствует. Не записывать и не показывать приватный текст ошибок/ключи/API-контекст. Если тип неизвестен, не утверждать время восстановления.
6. При 429 **не зацикливать повторные вызовы и не обходить квоты сменой ключей**. Для минутного/неизвестного лимита задать локальное ожидание (подсказка провайдера либо консервативный интервал), остановиться и дать Автору повторить позже. Для суточного лимита честно показать тип. Не делать фоновых списаний, автоматической покупки и безусловного переключения провайдера.
7. Отдельные проверки доступности модели расходуют запросы; не опрашивать Gemini по таймеру. Уровни, ДНК и решение Автора **никогда не меняются** из-за ошибки сети, паузы, refresh или 429.
8. Новая версия лимита из AI Studio должна задаваться конфигурацией для разных провайдеров и тарифов. Текущий интервал 17 с — **тестовая настройка под 5 RPM**, не универсальный факт Google.

## Контрольные тесты / критерии
- Непрерывный круг (preflight + восемь сфер + Желток) не превышает 5 RPM только из-за собственного автоматического потока в одном браузере.
- Повторный запуск после refresh / 429 берёт текущую `expectedRevision` и выполняет только `nextEggAutomationStep`. Результаты прошлых шагов неизменны.
- Если уже есть восемь результатов, при продолжении идёт **только смысловой разбор Желтка**, без повторной проверки модели и повторных сфер.
- Ошибка 429 с суточной квотой не вызывает бесконечных автоматических повторов; в интерфейсе ясно, что это квота провайдера, а не проблема БД или Vercel.
- Никаких скрытых режимов фоновой генерации или расхода токенов без видимого действия Автора.
