# Egg v0.9 — контролируемые выпуски из GitHub на Vercel

## Зачем изменён режим

При разработке небольшие последовательные коммиты приводили к десяткам автоматических Vercel-развёртываний. Vercel вернул \`402 api-deployments-free-per-day\` (лимит бесплатного тарифа). Важно: **Ignored Build Step не решает эту проблему**, потому что отменённые сборки могут учитываться в квоте deployments.

## Изоляция по ветке

В \`vercel.json\` установлено:

\`\`\`json
{
  "git": {
    "deploymentEnabled": {
      "prototype/design-brief-sketch-gates": false
    }
  }
}
\`\`\`

Это отключает **автоматические Git deployments только при пуше в данную ветку**. Другие ветки, включая production, не затронуты. Применение зависит от Git-integrated Vercel project, который использует эту конфигурацию.

Изменение не удаляет существующие тестовые URLs и не отключает возможность **осознанного ручного preview deployment** по Git reference.

## Новый рабочий цикл

1. Разработка: коммиты в \`prototype/design-brief-sketch-gates\` (без автоматических публикаций).
2. Проверка: \`npm run egg:verify\` — tests Egg + интерфейс Автора, серверный TypeScript, Vite build; выполнить в изолированном окружении без секретов.
3. Выпуск: **только после успешно пройденной проверки** создать одно Preview Deployment для текущего commit SHA / этой ветки. GitHub branch и commit SHA должны совпадать с протестированными.
4. Проверка работы: убедиться в \`READY\`, затем проверить /ru/unocalc, /api/egg, /api/mcp, тестовую запись/чтение через отдельный Supabase.
5. Если Vercel вновь отклонит deploy из-за квоты, **не делать десятки повторов** и не переключать production target. Не называть локальную сборку опубликованной.

## Как вручную запускать публикацию

В интерфейсе Vercel открыть проект \`project-a4e09c64-fce9-4015-a358-ceb6b53fe078\` → **Deployments** → **Create Deployment** → указать Git branch \`prototype/design-brief-sketch-gates\` или проверенный commit SHA → выбрать **Preview**, не Production.

При использовании API должна быть указана Git source с \`ref=prototype/design-brief-sketch-gates\`, соответствующий SHA и preview-target; не использовать \`target=production\`.

**Важно для новой БД:** \`EGG_SUPABASE_URL\`, \`EGG_SUPABASE_PUBLISHABLE_KEY\`, \`EGG_SUPABASE_SECRET_KEY\` привязаны к **Preview + этой Git branch**. Секрет не копировать в репозиторий, frontend или пользовательские файлы. Если ручное развёртывание не распознало привязку к ветке, завершить его без теста данных и исправить scope переменных.

## Что это не решает

- На данный момент автономная база \`egg-engine-test\` создана и SQL применён, но end-to-end HTTP тест записи/чтения ещё предстоит после нового preview deployment.
- Отключение авторазвёртываний не отменяет необходимости тестов и отдельной проверки корректной аутентификации.
- При последующем переносе «Яйца» в **выделенный репозиторий и Vercel project** правило автоматических сборок нужно проектировать заново, а не слепо копировать.
