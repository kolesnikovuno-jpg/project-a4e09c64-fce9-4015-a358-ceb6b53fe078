# EGG · Вкладка «Желток» · UI/UX specification v0.1

Статус: реализованный интерфейсный прототип. Концепция взаимодействия проходит пользовательскую проверку, это не окончательное утверждение дизайна/движка.
Дата: 2026-11-05.

## Цель

Представить текущую формирующуюся форму в центре восприятия, а вклады восьми функциональных сфер — как интерактивную орбиту. Визуальная информация по умолчанию первична; текст краткий, но доступно разворачивается до оригинальных заданий, решений, источников и файлов. Желток остаётся интегратором, а не дополнительной папкой документов.

## Композиция

1. **Центральная сцена** — актуальный визуальный образ; интерактивный просмотр. Для ранних концептов, не имеющих подтверждённой модели, используется **явно помеченная** условная пространственная схема, а не вымышленное изделие.
2. **Восемь сфер по периметру** — Маркетинг, Право, Производство, Комплектация («Материя» как пользовательская подпись), Ритейл, Коммерция, Тестдрайв, Дизайн. Нажатие только выбирает сферу и не меняет её статус.
3. **Боковая панель** — при отсутствии выбора показывает краткий паспорт ДНК/концепта; при выборе — состояние, задачу, сжатый вклад и кнопку «Развернуть».
4. **Развёрнутая панель** — реальные задачи/находки/решения/связанные файлы с исходными текстами и статусами.
5. **Нижняя строка** — напоминание о демонстрационном статусе графики и о том, что просмотр не утверждает решения.

## Реализованное поведение

- Роут: \`/egg/yolk\`; с проектом: \`/egg/yolk?project=<uuid>\`.
- Кнопка «Желток · 3D» добавлена в шапку существующей страницы Яйца.
- Поворот условной объёмной схемы кресла: drag/touch/стрелки; масштабирование: колесо; кнопка сброса ракурса.
- По запросу пользователя можно открыть собственный **локальный GLB** до 40 МБ. Он проверяется по магическому заголовку \`glTF\` и отображается через \`model-viewer\` — не загружается на сервер и не сохраняется как утверждённая модель.
- Данные проекта (ревизия, задачи, находки, статус концепции, ссылки на артефакты) читаются из существующего защищённого \`/api/egg-project-state\` с авторизацией Supabase.
- Без проекта / без разрешённого сеанса показывается **честно обозначенная демонстрация**, без вымышленных результатов работы сфер. Авторизация не обходится.
- Вкладка только читает состояние; ни один клик по сфере, просмотр 3D или раскрытие панели не изменяет Core.
- Отдельная кнопка ведёт в существующее рабочее пространство соответствующей сферы.

## Из чего строится информация

В текущем прототипе:
- ДНК = исходная идея \`project.seed.text\`, не заменяемая текстом AI.
- Концепт = последняя утверждённая версия, если есть; иначе последнее предложенное направление с отдельным статусом; если версий нет — исходный текст.
- Статус сферы = производный от реальных задач; «нет заданий» не означает «сфера завершена».
- Краткий вклад = последняя находка или текст задачи, явно **не** доказанный автоматически.
- Полный вклад = истории задач, находок, авторских решений и зарегистрированных материалов по сфере.
- Условная визуализация = геометрическая иллюстрация, не техническая модель A «Объятие»; без подмены реального авторского эскиза.

## Что ещё не реализовано

- Серверная версия визуального концепт-пакета (\`hero image\`, \`model GLB/GLTF\`, \`thumbnails\`, \`materials\`, \`conceptVersion\`) и право Автора выбирать её.
- Автоматическая синхронизация GLB/эскиза и текущего подтверждённого варианта из Drive/Storage.
- Визуальные слои модели (материалы, технологии, повреждения, аннотации), привязанные к версиям.
- Содержательный движок Желтка (согласованность, доказательность, влияние сфер, противоречия) — сейчас это **интерфейс**, а не такой движок.
- Адаптированный компактный UX для каждой сферы, фильтры доказательности, полный документальный финальный пакет.
- Поддержка нескольких версий моделей и 3D для разных типов продуктов (видео, схема, интерактивная карта и др.), где не существует физического предмета.

## Условия для следующих итераций

1. На реальном кресле провести тест: Автор открывает 3D-контур, выбирает Материю, возвращается к ДНК, раскрывает сведения, видит актуальный статус.
2. Зафиксировать расхождения в понятности интерфейса, в том числе на iPad/Safari.
3. Сначала сформировать надёжный контракт визуального артефакта с версиями и правами, затем подключать автоматическое отображение настоящих эскизов/GLB.
4. Не считать добавление изображения доказательством реализуемости, изготовления или авторского утверждения.
