# EGG · языковая архитектура (RU / UA / EN)

## Цель

Сохранять **единый интерфейс** EGG на трёх языках без трёх отдельных версий экранов. Многоязычность закладывается в компоненты с самого начала, а окончательные формулировки и переводы уточняются по мере утверждения дизайна панелей.

## Устройство (реализовано)

- `src/i18n/config.ts`: коды `ru`, `uk`, `en`.
- `src/i18n/LanguageSwitcher.tsx` + `src/i18n/useLocale.ts`: выбор языка; на локализованных страницах меняется языковой сегмент URL при сохранении query `project` и `start`; `/egg/connect` и `/egg/yolk` остаются без языкового префикса для сохранения механизма авторизации и проектных ссылок.
- `src/components/egg/EggStablePreview.tsx`: общий EGG-контур, передающий текущий язык через `EggUiProvider` всем вложенным панелям.
- `src/i18n/eggUi.tsx`: единый **типизированный словарь интерфейса** RU/UA/EN с одинаковыми ключами, `useEggUi()` для компонентов и русским fallback для изолированного рендеринга.
- `src/test/Egg/eggUiArchitecture.test.tsx` и `eggLanguageSwitcher.test.tsx`: контракт словарей и сохранение маршрутов.

Словарь EGG отделён от большого словаря публичного сайта. Новый устойчивый элемент интерфейса добавляется сразу во все три локали в `eggUi.tsx`. Не сохранять переводы в базе проекта.

## Что переводим

Названия разделов и сфер, заголовки, кнопки, меню, подсказки, диалоги интерфейса, системные статусы и сообщения об ошибках. Рабочие панели переводятся **по мере окончательного утверждения их структуры и текстов**, а не массовым механическим переводом черновых описаний.

## Что не переводим автоматически

- Названия пользовательских проектов;
- карточки Поля и Материального, тексты, заметки, подписи к фотографиям;
- авторское намерение, исходную ДНК, утверждённый концепт;
- историю итераций, ответы ИИ и документы проекта;
- идентификаторы, типы сфер, статусы движка, payload API, ключи сохранения.

Их перевод возможен позднее **только как отдельная пользовательская операция**, с сохранением неизменённого оригинала. Изменение языка UI не является изменением содержимого проекта и не должно вызывать серверную запись.

## Правило для новой панели

1. Сперва определить структуру, функции, состояния и визуальный ритм.
2. Для каждого **служебного** текста создать ключ в `eggUi.tsx` для RU/UA/EN.
3. Вызывать `const {ui}=useEggUi();` и использовать `ui.key`, включая `aria-label` и placeholder.
4. Придерживаться адаптивной вёрстки, допускающей длинные переводы (перенос строк, `min-w-0`, без жёсткой ширины текста).
5. Данные проекта хранить и сравнивать по машинным ID/enum, не по текстам перевода.
6. Проверить UI в трёх языках, возврат к проекту, вход и синхронизацию; не менять workflow ради локализации.

## Текущее покрытие

Общий переключатель, навигация между мастерскими, меню, базовые действия Поля и Материального, ключевые заголовки Идеи/Концепта, полученное ДНК в Желтке, статус серверной синхронизации. **Внутренние инструкции и часть рабочих элементов ещё русскоязычные.** Их перевод отложен до утверждения соответствующих панелей. Это осознанный незавершённый этап, а не признак полной локализации.
