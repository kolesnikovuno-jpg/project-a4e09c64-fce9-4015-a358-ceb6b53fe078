## 2. Зафиксированная архитектура

Архитектурная правда: [EGG-Architecture/EGG_MASTER_CONTEXT.md](https://github.com/kolesnikovuno-jpg/EGG-Architecture/blob/main/EGG_MASTER_CONTEXT.md) + [DECISIONS.md](https://github.com/kolesnikovuno-jpg/EGG-Architecture/blob/main/DECISIONS.md). Эти источники принимают авторские решения, а не статус их программной реализации.

- Поле (материалы) → Авторская сфера **«Идея»** → Концепт/ДНК → восемь функциональных сфер → Желток, центральный синтез.
- Поток A: Маркетинг → Дизайн → Тест-драйв → Коммерция.
- Поток B: Право → Производство → Комплектация → Ритейл.
- Один результат каждой сферы → следующей сфере + радиальная нить в Желток; **не два AI-вызова**. Желток сопоставляет **полный комплект восьми**; решения и переходы фиксирует **Автор**.
- Пять уровней: Идея → Концепт → Прототип → Образец → Продукт; итерации внутри уровней.
- Желток показывает эфемерное, поворотное **пространственное поле как предварительную гипотезу**, а не гарантированно значимую CAD/3D-модель. Материал интерьера — **контекст**, не приказ помещать объект на стену.
- **Диалог и отдельная генерация изображений — вспомогательные режимы**, не замена EGG-цикла.
- Текстовая интерпретация ИИ должна быть отделена от утверждённого Автором факта. Самостоятельное изменение ДНК AI запрещено.
- Исторически некоторые документы называют верхнюю сферу «Автор» и следующую «Концепт», а современный интерфейс — «Идея» и «Концепт»; это терминологические слои **одной системы**, не причина создавать вторую систему. Не переписывать старые ADR без явного решения Автора.

## 3. Текущая реализация — что проверено / чего пока нет

**Проверено кодом, тестами и сборкой:** существующие сферы, две последовательные ветви, один потоковый синтез, сохранение версионированного Yolk review; привязка поля к текущему намерению; морфологическая гипотеза после восьми сфер с ссылками на **обе** ветви; мягкое изменение той же пространственной точки/поля, не новая 2D-картинка; отклонение неподтверждённых координат. Проверка `npm run egg:verify`: 240 passed / 5 skipped на deployment `bd4057c8`.

**Не установлено / не реализовано полностью:**
- Прямой реальный end-to-end тест **новой** идеи через все восемь сфер → синтез ИИ → утверждение Автора → обновлённая форма.
- **Граница 3D:** с 2026-11-18 добавлен `Spatial Form Engine v0.1`: для намерения «кресло», и только после полного подтверждённого восьмисферного синтеза с морфологией, создаётся параметрическая геометрия (сиденье/спинка с отверстием/опоры) и экспортируемый GLB. Это **реальный 3D-файл, но не семантическое восстановление точной картинки, не индустриальный CAD и не проверенная конструкция**. Неизвестные объекты по-прежнему только в абстрактном поле; пользователю доступно «Форма / Поле».
- Утверждённая ДНК как единая отдельная финальная запись Автора на всех этапах.
- **Межустройственная синхронизация**: добавлен отдельный серверный слой `egg_workspace_snapshots` (scope `idea`, `field`, `matter`), RLS и проверка владельца, условное обновление по revision. Код синхронизации в рабочей ветке; реальный тест между двумя пользовательскими устройствами ещё **не подтверждён**. При отсутствии соединения черновики продолжают оставаться локальными. Видеофайлы IndexedDB пока не переносятся — только карточки/метаданные.
- Изображения и референсы не гарантируют видимость/доступность через другой браузер. Не переносить и не удалять пользовательские данные автоматически.

**Чистый запуск для сквозного теста:** на `/egg/connect` после входа доступна форма **«Начать чистый проект EGG»**. Она создаёт одну новую запись в **той же базе**, без `seed` и без переноса старых материалов/циклов, после чего открывает `/ru/egg?project=<NEW_UUID>&start=field`. Реальная новая запись появляется только по действию Автора (под его сессией). Её нельзя путать с новой версией программного репозитория.

**Факт по базе на 2026-11-17:** запись `01b3d29f-...`, revision **23**, **один** элемент в `flowCycles`, последний статус **`awaiting_author`**. Это НЕ доказывает, что находящаяся сейчас на локальном холсте «Отдельная нота» прошла этот цикл. Исторический поток может относиться к другой идее; прежде чем принимать/передавать ДНК проверять `ideaHandoff.intent`, `cycle.id` и `synthesis.id` против текущего намерения. Никогда не нажимать «Принять» автоматически ради демонстрации.

## 4. Правило непрерывности для будущих чатов и инструментов

**Перед первым изменением:**
1. Прочесть **этот файл**, архитектурный [DECISIONS.md](https://github.com/kolesnikovuno-jpg/EGG-Architecture/blob/main/DECISIONS.md) и актуальный [IMPLEMENTATION_STATUS.md](https://github.com/kolesnikovuno-jpg/EGG-Architecture/blob/main/IMPLEMENTATION_STATUS.md).
2. По GitHub проверить **текущую ветку, изменяемый файл и HEAD**. По Vercel — **текущий alias**, SHA, state и **ID Vercel-проекта**. По EGG-проекту — `projectId`, `revision`, **принадлежность идеи** текущему циклу. Не выбирать случайный preview URL или Lovable-состояние.
3. Одна функциональная задача → изменения **только в подтверждённой ветке** → `npm run egg:verify` → Vercel READY → проверка alias+SHA. Если сборка не готова — говорить **«не проверено»**, а не «опубликовано».
4. Фиксировать итог **в [EGG_CHANGELOG.md](EGG_CHANGELOG.md)**: смысл → конкретные файлы/коммит → тесты → опубликованная версия → открытые риски. Новый авторский принцип отдельно заносить в [DECISIONS.md](https://github.com/kolesnikovuno-jpg/EGG-Architecture/blob/main/DECISIONS.md); не смешивать решение с реализацией.
5. Не считать локальный черновик утверждённым или серверным. Перед сменой устройства обеспечить экспорт/синхронизацию; при отсутствии — прямо предупредить.

**Отказ от параллельных «версий правды»:** ни другой GitHub-репозиторий, ни новый Vercel-проект, ни отдельная Supabase-база не создаются для этой линии без явного решения Автора. **Новую пользовательскую запись EGG-project ID можно и нужно создавать отдельно** для чистого эксперимента/новой идеи; это нормальная функциональность системы, не новая кодовая ветка. Старые записи не удалять.
