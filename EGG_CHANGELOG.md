## 2026-11-17 · Эфемерная форма Желтка и восьмисферная морфология — реализовано в коде
- `src/lib/eggYolkFormBasis.ts`, `src/components/egg/EggYolkExperience.tsx`: предварительное поле следует текущему намерению Автора. Старый цикл другой идеи не должен влиять на новое поле.
- `src/lib/eggYolkSemantic.ts`, `src/lib/eggFlowAutomation.ts`, `api/egg-flow-ai.ts`: один запрос синтеза после восьми сфер может вернуть **морфологическую гипотезу** (8 параметров 0..1, источник из обеих ветвей), без отдельной генерации изображений и без изменения ДНК.

- `src/components/egg/EggYolkSemanticPanel.tsx`: смысловые основания морфологии доступны в раскрывающемся разделе, не поверх формы.

## 2026-11-17 · Разделение Идеи, Желтка и генератора картинок
- Генерация 2D изображений перемещена в свернутый архив экспериментов. «Желток · 3D-поле» — основной переход от Идеи.
- Фото реального интерьера можно прикладывать как контекст, а не утверждённую форму; визуальный генератор способен использовать фото в режиме image edits, но это не основной маршрут EGG.
- **Открыто:** браузерный локальный черновик и серверная запись ещё не синхронизированы; версия Идеи на разных устройствах может различаться.

## Нерешённое, в порядке важности
1. Серверный снимок авторского черновика с принадлежностью к конкретному EGG-проекту и стабильной синхронизацией между устройствами, без перезаписи исторического цикла.
2. Сквозной сценарий одной реальной идеи: Автор → подтверждение входа → восемь сфер → Желток → проверка морфологии → авторское решение. Не использовать для этого случайный старый цикл.
3. Версионированная утверждённая ДНК и дальнейшая проекция в полноценное 3D. Пока поле — интерактивная проекция 3D-координат.

## Контроль каждой следующей задачи
Каждый существенный коммит должен получать строку: **изменение → тест → Vercel SHA+alias → граница проверки → следующий шаг**. Если предыдущий коммит не прошёл тесты или домен остался на старой версии — явно сообщить, не выдавать состояние за готовое.
